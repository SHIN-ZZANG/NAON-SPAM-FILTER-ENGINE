Naon-Spam-Filter

스팸필터 관리 화면과 Rspamd 판정 연동을 먼저 갖춘 초기 기획을, 메일을 직접 받아 판정하고 격리한 뒤 정상 메일만 James로 넘기는 스팸필터 제품으로 확장합니다.
판정은 검증된 오픈소스 엔진 Rspamd를 기반으로 하고, 국내 스팸 규칙과 학습은 자체 엔진으로 더합니다.

개발 단계의 기획 변경입니다.
운영 중인 시스템에는 영향이 없습니다.

스팸필터는 엔진 프로젝트와 관리 프로젝트 두 개로 나눠 만듭니다.
엔진은 Docker 묶음으로, 관리 프로젝트는 관리 Docker로 각각 배포합니다.
두 프로젝트는 서버 DB를 함께 씁니다.

엔진 Docker 묶음 (엔진 프로젝트, 메일 처리)

스팸필터 엔진, Rspamd, Valkey를 한 묶음으로 함께 띄우고 함께 멈춥니다.
운영자는 이 묶음 하나로 다룹니다.
Rspamd와 Valkey는 공식 배포본을 그대로 쓰므로, 업그레이드는 버전만 바꾸면 됩니다.
각 프로그램이 멈추면 Docker가 자동으로 다시 시작합니다.

관리 Docker (관리 프로젝트)

관리자 로그인, 격리함 열람·해제·삭제 기록, 처리 이력·통계 조회, 점수 정책·국내 스팸 규칙·허용/차단 목록 관리를 맡습니다.
관리 화면도 관리 Docker 안에 함께 들어 있습니다.
격리 해제, 격리 메일 원문 보기, 학습 반영처럼 엔진만 할 수 있는 일은 엔진에 요청합니다.
관리 Docker를 고쳐 다시 올리거나 멈춰도 메일 처리는 계속됩니다.

서버 DB (함께 쓰는 데이터)

서버에 별도로 구성한 DB입니다.
엔진과 관리 프로젝트가 함께 쓰고, 데이터마다 기록하는 쪽은 한 곳입니다.
엔진은 처리 이력, 격리 메일 목록, 전달 상태, 학습 데이터를 기록하고, 정책·규칙·허용/차단 목록을 읽어 판정에 씁니다.
관리 프로젝트는 정책·규칙·허용/차단 목록, 관리자 계정, 열람 기록을 기록하고, 처리 이력과 격리 메일 목록을 읽어 보여 줍니다.

서버 Nginx (관리자 접속 창구)

서버에 별도로 구성한 Nginx가 관리자의 접속을 관리 Docker로 넘깁니다.
Nginx에는 화면 파일을 두지 않습니다.

  • Valkey (Redis 필요): Rspamd는 학습·평판·이력 데이터를 저장할 Redis가 반드시 필요합니다.
    여기에 Redis와 호환되는 오픈소스 저장소인 Valkey를 씁니다(Redis를 그대로 써도 됩니다).
    스팸필터의 데이터는 Redis가 아니라 서버 DB에 저장합니다.
  • 관리 프로젝트(관리 Docker): 관리자가 이력·통계, 점수 정책, 국내 스팸 규칙, 격리함을 다루는 관리 화면과 관리 기능입니다.
  • James: Docker 밖에 있는 기존 메일함 서버입니다.
    스팸필터 엔진을 거친 메일만 받습니다.
Rspamd란? (소스: github.com/rspamd/rspamd · 공식 사이트: rspamd.com)
무료 오픈소스 스팸 판정 엔진입니다(Apache 2.0 라이선스).
메일을 넘기면 발신자 인증(SPF·DKIM·DMARC), 스팸 발송지 평판, 내용 규칙, 학습 결과로 점수를 매겨 돌려줍니다.
메일을 받거나 보관하지 않고 판정만 합니다.
해외에서 메일 서버에 많이 쓰이는 검증된 엔진이며, 범용 규칙은 커뮤니티가 계속 갱신합니다.
스팸필터 엔진은 Rspamd 점수에 자체 판정(국내 스팸 규칙·학습) 점수를 더해 최종 결정합니다.

변경 배경과 기대 효과

관리 화면에서 한 걸음 더 나아가, 메일을 직접 거르는 제품으로 확장합니다

초기 기획은 판정을 Rspamd, 수신·격리를 James에 맡기고 관리 화면과 판정 연동을 먼저 갖춘 단계입니다.
이번에는 그 위에서 메일을 받아 거르고 격리하고 정상 메일만 넘기는 일까지 맡습니다.

메일함 서버(James)를 앞에서 보호합니다

스팸필터 엔진이 인터넷 메일을 먼저 받아 거르므로 James가 공격과 스팸 폭주로부터 보호됩니다.
스팸은 James에 닿기 전에 격리되고, 위험 첨부도 앞단에서 걸러 냅니다.

판정 품질을 믿을 수 있어야 합니다

판정의 기반은 이미 많은 메일 서버에서 쓰이는 Rspamd에 맡깁니다.
Rspamd가 약한 국내 스팸은 자체 엔진으로 보강합니다.

유지보수가 쉽고, 한쪽이 멈춰도 다른 쪽 일은 계속됩니다

범용 스팸 규칙은 Rspamd 커뮤니티가 갱신하므로 버전만 올리면 됩니다.
우리는 국내 스팸 규칙, 처리 정책, 격리, 전달에만 집중합니다.
메일 처리는 엔진 프로젝트, 관리 기능은 관리 프로젝트가 맡아 고칠 곳이 분명합니다.
관리 프로젝트를 고쳐 다시 올려도 메일 처리에 영향을 주지 않습니다.
엔진이 잠시 멈춰도 관리 화면에서 로그인, 이력·격리 목록 조회, 정책·규칙 수정을 할 수 있습니다.

관리자에게 달라지는 점

로그인

관리 화면은 스팸필터 전용 관리자 계정으로 로그인합니다.

격리함

관리 화면에서 바로 보고 해제·삭제합니다.
격리 사유(스팸 점수·차단 목록·위험 첨부·바이러스)와 걸린 규칙이 한글로 표시됩니다.

국내 스팸 규칙 관리 신규

관리 화면에서 규칙을 추가·수정하고, 저장 전에 어떤 메일이 걸리는지 시험해 볼 수 있습니다.

학습

격리 해제, "스팸으로 학습" 표시, 사용자의 Spam 폴더 이동이 판정 정확도를 높이는 데 쓰입니다.

이력·통계

모든 메일의 판정 결과와 이유가 빠짐없이 기록됩니다.
점수 정책 화면은 지금처럼 3단계 기준을 정합니다.

감수할 점

국내 스팸은 처음에 약할 수 있음

Rspamd 기본 규칙은 영어권 위주입니다.
시범 운영으로 확인하고 국내 스팸 규칙과 학습으로 보강합니다.

Rspamd를 함께 운영

버전을 고정해 두고, 올릴 때는 검증 환경에서 판정 변화를 확인한 뒤 반영합니다.
Rspamd가 멈췄을 때의 처리 기준도 정해 둡니다.

엔진 묶음이 멈추면 수신도 멈춤

보낸 쪽이 재시도하므로 짧은 중단은 지연으로 끝납니다.
엔진은 자동으로 다시 시작되고, 이미 받은 메일은 재시작 후 이어서 전달됩니다.
엔진이 멈춘 동안에도 관리 화면에서 로그인, 이력·격리 목록 조회, 정책·규칙 수정은 할 수 있습니다.
격리 해제, 격리 메일 원문 보기, 학습 반영은 엔진이 다시 살아날 때까지 할 수 없고, 화면에 "엔진 응답 없음"을 표시합니다.
운영 단계에서는 엔진 묶음의 이중화와 별도 상태 감시·알림이 필요합니다.
관리 Docker나 서버 Nginx가 멈춰도 메일 처리는 계속됩니다.

운영할 묶음이 둘

엔진 Docker 묶음과 관리 Docker를 각각 배포하고 관리합니다.
두 프로젝트가 서버 DB를 함께 쓰므로, 데이터마다 기록하는 쪽을 한 곳으로 지킵니다.

격리함 용량

스팸을 모두 격리하므로 보관 기간과 용량 관리가 필요합니다.

업체가 제공하는 스팸 패턴과 규칙은 가져오지 않습니다.

정해야 할 사항

  1. 판정 점수 기준 확정 (초기값: 격리 15 / 제목 태그 10 / Spam 폴더 6)
  2. 바이러스 검사 범위: 위험 첨부 격리만 할지, 백신(ClamAV 또는 사내 백신)을 연동할지
  3. 격리 메일 보관 기간, 격리함 열람 권한자
  4. Rspamd 또는 판정 오류 시 처리: 수신을 잠시 미룰지, 검사 없이 전달할지
  5. Rspamd 버전 업그레이드 주기와 검증 절차
  6. 스팸스나이퍼 사용권 계약 확인 (설정 이관 범위)
  7. 운영 단계 이중화 방식
